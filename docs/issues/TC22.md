# TC22: Rechazar un contrato de entrada inválido - <caso>

Requisito: @REQ-CLI-05.

Archivo: `src/test/resources/features/climatizacion.feature`.

## Precondiciones y resultado esperado

Barista se reinicia y alcanza su estado inicial mediante `barista-state.feature`; no depende del caso anterior. Climatización recibe tres booleanos: temperatura alta, presencia y apertura prolongada.

**Alcance revisado el 16 de octubre de 2026:** cinco estructuras inválidas: campo ausente, lista vacía, dos valores, cuatro valores y null. Son comprobaciones adicionales del rechazo estructural observado, separadas de las reglas funcionales de la profesora. Se retiró el ejemplo `[true, "si", false]`: exigir HTTP 400 para ese tipo carecía de una especificación independiente. Su respuesta 200/noDefinida se conserva como observación exploratoria pendiente de especificación en `docs/DEFECTOS.md`, no como bug confirmado. No se cambió la expectativa de ese ejemplo a 200 ni se lo marcó como omitido.
